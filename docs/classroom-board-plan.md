# 교실 대시보드(전자칠판) 기획서

> 작성일: 2026-08-28 · 상태: 초안
> PLANSCHOOL(교사용 바탕화면 대시보드)의 확장 기능.
> 교사가 자기 대시보드에서 "교실로 보내기"를 누르면, 교실 전자칠판(대형 디스플레이)에
> 학급용 화면이 뜨고 실시간으로 갱신된다.

---

## 1. 한 줄 요약

**교사 대시보드의 학급 정보(시간표·급식·일정·공지)를 교실 전자칠판에 실시간으로 띄워주는 학생용 화면.**

- 교사용 대시보드 = 조작하는 쪽 (리모컨)
- 교실 전자칠판 = 보여주는 쪽 (수신 전용, 조작 없음)

## 2. 왜 만드는가

- 담임 교사는 이미 PLANSCHOOL에 학급 시간표를 입력하고 있다. 같은 정보를 칠판에 손으로 다시 쓰거나 판서로 공지하는 일이 반복된다.
- 전자칠판은 대부분 브라우저가 내장되어 있어, URL 하나만 띄워두면 되는 형태가 학교 현장에서 가장 도입 장벽이 낮다.
- 아침 조회·쉬는 시간에 학생들이 스스로 "다음 수업·오늘 급식·일정"을 확인하게 되어 교사의 반복 안내가 줄어든다.

## 3. 사용자 시나리오

### 시나리오 A — 최초 연결 (학기 초 1회)
1. 교사가 설정 → **교실 화면** 메뉴에서 "교실 코드 만들기"를 누른다. (예: `QK3M7P`)
   - 메뉴 위치: 설정의 "학교 · 일정" 그룹 (교시 시간·학사일정 옆)
   - **담임만 노출**: 프로필의 `homeroom_class`가 비어 있으면 메뉴 자체를 숨긴다.
     (학급 시간표 탭과 동일한 판별·동일한 방식 — "담임 학급을 입력하면 학급 기능이 열린다"는 기존 규칙 유지)
2. 전자칠판 브라우저에서 `.../board` 를 연다.
3. 칠판 화면에 뜬 코드 입력창에 `QK3M7P` 를 입력하면 연결 완료.
4. 이후 칠판은 재부팅해도 같은 화면으로 복귀한다. (코드를 기기에 저장)

### 시나리오 B — 평소 (자동)
- 칠판은 항상 학급 기본 화면을 보여준다: 오늘 날짜·시계, 학급 시간표(오늘), 현재 교시 표시, 오늘 급식, 이번 주 학사일정, D-Day.
- 교사가 대시보드에서 학급 시간표를 수정하면(이번주 교환 포함) 칠판에 자동 반영된다.

### 대시보드 진입 버튼 (일상용)
- 프로필 사진(쪽지함) 위젯 = `cheer` 위젯의 빈 왼쪽 공간에 "🖥️ 교실 화면" 버튼을 추가한다.
  - **담임(`homeroom_class` 입력자)일 때만 렌더** — 비담임은 지금과 완전히 동일한 화면.
  - 원형 프로필 버튼은 그대로 오른쪽, 새 버튼은 `flex-1`로 왼쪽 남는 폭을 차지 (좁아지면 텍스트 말줄임).
  - 담임 판별은 위젯이 아바타 로드에 이미 쓰는 `fetchProfileRow` 응답의 `homeroom_class` 재사용 (추가 쿼리 없음).
  - 동작: "교실로 보내기" 패널을 연다. 교실 코드가 아직 없으면 설정 → 교실 화면으로 안내.
  - 페어링·코드 관리는 설정(학교 · 일정 그룹)에 유지 — 이 버튼은 매일 쓰는 조작 전용.

### 시나리오 C — 교사가 보내는 순간
- 교사가 대시보드의 "교실로 보내기" 패널에서:
  - **공지**: "3교시 후 체육관으로 이동" 입력 → 전송 → 칠판 상단에 크게 표시
  - **타이머**: 10분 타이머 전송 → 칠판에 전체화면 카운트다운
  - 공지는 지우기 전까지 유지, 타이머는 종료되면 사라진다.

## 4. 기능 범위

### MVP (1차)
| 기능 | 설명 |
|---|---|
| 교실 코드 페어링 | 교사당 교실 1개. 친구 코드와 같은 6자리 코드 방식. **담임(`homeroom_class` 입력자)만 발급 가능** — 메뉴 숨김은 물론 서버(RPC/RLS)에서도 `homeroom_class is not null` 검사 |
| 학급 기본 화면 | 시계·날짜, 학급 시간표(오늘, 현재 교시 하이라이트), 급식, 주간 학사일정, D-Day |
| 실시간 반영 | 시간표·설정 변경이 칠판에 자동 반영 (Supabase Realtime) |
| 공지 보내기 | 텍스트 공지 전송/해제. 칠판에 크게 표시 |
| 원거리 가독성 | 교실 뒤에서도 읽히는 큰 글씨 전용 레이아웃 (16:9 고정) |

### 2차 이후 (후보)
- 수업 타이머 / 쉬는 시간 자동 표시
- 자리 배치도, 청소 당번표
- 칠판 테마(학급 색상), 다크 모드(전자칠판 번인 방지)
- 학년·학교 공용 화면(여러 반 순환 표시)

### 하지 않는 것
- 칠판에서의 입력·조작 (수신 전용을 유지해 복잡도와 보안 문제를 차단)
- 학생 개인정보 표시 (이름·사진 등은 MVP에서 제외)

## 6. 기술 설계

### 6.1 구조: 같은 프로젝트에 라우트 추가 (신규 저장소 X)

- `/board` 라우트를 이 프로젝트에 추가하고 lazy import로 번들 분리.
- 이유:
  - 시간표·급식·일정 위젯과 API 계층을 그대로 재사용 (신규 프로젝트면 전부 복사 → 이중 유지보수)
  - DB 스키마·RLS 변경이 잦은데, 저장소가 갈리면 동기화 사고 지점이 된다
  - 배포·도메인·환경변수 그대로 하나로 유지
- 신규 저장소가 맞는 경우는 스택이 달라지거나(네이티브 앱) 담당 팀이 분리될 때뿐.

### 6.2 인증: 칠판은 로그인하지 않는다

전자칠판은 공용 기기라 교사 계정 로그인은 위험(개인 쪽지·할 일 노출). 대신:

- **읽기**: `get_board_view(p_code)` — security definer RPC 하나로 칠판에 필요한 데이터만 골라 반환
  (학급 시간표 + 이번주 교환, 급식용 학교 코드, 학사일정, D-Day, 공지, 교시 시간).
  개인 시간표·할 일·쪽지는 반환 자체를 안 하므로 코드가 유출돼도 학급 정보 이상은 노출되지 않는다.
- **실시간**: 코드별 Realtime broadcast 채널 `board:{code}` 구독.
  교사 쪽에서 변경 시 채널로 "갱신됨" 신호만 쏘고, 칠판은 신호를 받으면 RPC를 다시 호출한다.
  (payload에 데이터를 싣지 않으므로 채널을 엿들어도 얻는 게 없음)
- **코드 재발급**: 코드가 알려졌다고 판단되면 설정에서 재발급 → 이전 코드는 즉시 무효.

### 6.2.1 칠판에서 교사 영역 진입 차단 (핵심 요구사항)

교실 칠판은 학생 앞에 상시 노출되는 공용 기기이므로, 어떤 경로로도 교사 대시보드에
진입할 수 없어야 한다. 이 격리는 저장소 분리가 아니라 **세션 부재 + RLS**로 보장한다.
(프로젝트를 새로 파도 같은 DB를 쓰는 이상 보호 수단은 동일하게 이 둘이다.)

1. **페어링된 칠판 기기에서는 진입 시 강제 로그아웃** — 코드가 저장된 기기에서 `/board`가
   열리면 남아 있는 로그인 세션을 즉시 `signOut()` 처리한다. 교사가 실수로 칠판 기기에서
   로그인했더라도 칠판 화면으로 돌아오는 순간 세션이 소멸한다.
   - **예외: 미리보기 모드** — 페어링되지 않은 로그인된 브라우저(교사 본인 PC)에서 열면
     세션을 유지하고 코드도 기기에 저장하지 않는다. 교사가 칠판 화면을 미리 확인하는
     용도이며, 화면에 미리보기 표시가 뜬다. 설정 → 교실 화면의 "미리보기" 버튼이
     `/board?code=…`로 이 경로를 연다. (세션이 유지되는 기기는 교사 본인의 브라우저뿐이므로
     칠판 격리 목적과 충돌하지 않는다)
2. **칠판 화면에는 대시보드로 가는 링크·버튼이 일절 없다** — 설정, 로그인, 뒤로가기 유도 요소 금지.
3. **세션 없는 브라우저는 RLS에 의해 아무 데이터도 못 읽는다** — 칠판이 가진 것은
   교실 코드뿐이고, 코드로 호출할 수 있는 것은 `get_board_view` RPC 하나다.
   반환값에 학급 정보 외(개인 시간표·할 일·쪽지·프로필)를 포함하지 않으므로
   코드가 유출돼도 노출 범위는 칠판에 이미 보이는 내용과 같다.
4. **URL 조작 대비** — 칠판 브라우저는 전자칠판의 키오스크 모드(URL 고정)로 잠그는 것을
   설치 안내에 포함한다. 잠그지 않아 로그인 화면까지 이동하더라도, 위 1~3에 의해
   계정 정보 없이는 아무것도 볼 수 없다.

### 6.3 데이터 모델

```sql
create table public.classroom_boards (
  id         uuid primary key default gen_random_uuid(),
  owner_id   uuid not null references auth.users(id) on delete cascade,
  board_code text not null unique,          -- 6자리, generate_friend_code()와 같은 방식
  notice     text,                          -- 현재 공지 (null이면 없음)
  notice_at  timestamptz,
  created_at timestamptz default now(),
  unique (owner_id)                         -- MVP: 교사당 1개
);
-- RLS: owner만 select/insert/update/delete. 칠판은 RPC로만 접근.
```

- 시간표·급식·일정·교시 시간은 기존 테이블/프로필을 그대로 사용 (칠판 전용 복사본을 만들지 않는다).
- 공지처럼 "칠판에만 존재하는 상태"만 `classroom_boards`에 둔다.

### 6.4 기존 코드 재사용 지점

| 칠판 요소 | 재사용 대상 |
|---|---|
| 학급 시간표 | `fetchTimetable(is_class=true)` + `weekly_timetable.classMap` |
| 현재 교시 판정 | `NowTime`/`Messages`의 교시 판정 로직 → 공용 유틸로 추출 |
| 급식 | `SchoolMeals` 위젯의 NEIS 연동 |
| 학사일정 | `Schedule` 위젯 API |
| 교시 시간 | `profiles.period_schedule` |
| 코드 생성 | `generate_friend_code()` 패턴 |

※ 교시 판정 로직이 현재 3곳(NowTime, Messages, 칠판 예정)에 중복되므로, 이번 기회에 `src/lib/periods.js` 같은 공용 모듈로 추출하는 작업을 선행하는 것을 권장.

## 7. 개발 단계

1. **0단계 — 리팩터링** ✅ 완료 (2026-08-28): 교시 판정·시간표 병합 로직을 `src/lib/periods.js`로 추출. NowTime·Messages·Timetable·Settings가 공유.
2. **1단계 — 페어링** ✅ 코드 완료 (2026-08-28): `supabase/classroom_board.sql`(테이블·RLS·`issue_board_code`·`get_board_view`) + 설정 → 교실 화면 섹션(담임만 노출) + `/board` 코드 입력·자동 복귀 화면. **SQL은 Supabase SQL Editor에서 직접 실행 필요.** 담임 해제 시 `get_board_view`가 null을 반환해 칠판이 연결 화면으로 돌아간다(열어둔 결정 → 안전한 쪽으로 확정).
3. **2단계 — 기본 화면** ✅ 코드 완료 (2026-08-28): `supabase/classroom_board_v2.sql`로 `get_board_view` 확장(학급 시간표+이번주 classMap·교시 시간·학사일정·D-Day·학교 코드 — 개인 데이터는 반환 안 함, **SQL 수동 실행 필요**). 칠판 레이아웃: 상단 학급명·날짜·시계·현재 교시 / 좌측 오늘 시간표(현재 교시 하이라이트) / 우측 급식(NEIS 직접 조회, 알레르기 표기 제거)·이번 주 일정(NEIS+직접 추가 병합)·D-Day / 하단 공지 바. 3단계 전까지는 1분 폴링으로 갱신.
4. **3단계 — 실시간** ✅ 코드 완료 (2026-08-28): 칠판이 `board:{code}` broadcast 채널 구독, 교사 쪽은 위젯들이 이미 쏘는 window 이벤트(timetable/school-events/dday/homeroom-change)에 편승해 App에서 1초 디바운스로 신호 발송(payload 없음). 재발급·연결 끊기 시 이전 코드 채널로도 신호를 쏴 칠판이 즉시 연결 화면으로 복귀. 웹소켓 끊김 대비 5분 폴링+online 복구 폴백 유지. 추가 SQL 없음.
5. **4단계 — 공지 보내기** ✅ 코드 완료 (2026-08-28): 프로필 사진(cheer) 위젯을 담임일 때만 반반 분할해 "🖥️ 교실 화면" 버튼 추가 → "교실로 보내기" 패널(공지 띄우기/내리기, 미리보기 링크, 미연결 시 설정 안내). 공지는 broadcast 신호로 칠판 맨 윗줄에 즉시 반영. 추가 SQL 없음(1단계 update 정책 사용).
6. QA: 전자칠판 실기기(브라우저 종류·해상도) 확인 후 배포
